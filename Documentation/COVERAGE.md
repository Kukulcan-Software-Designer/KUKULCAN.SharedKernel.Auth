# Code Coverage

## Scope

Coverage targets the production `KUKULCAN.SharedKernel.Auth` assembly.

Test assemblies and compiler-generated code are excluded.

The CI coverage workflow executes:

- UnitTests;
- PostgreSQL integration tests;
- SQL Server integration tests;
- MySQL integration tests.

Each suite publishes its own Cobertura artifact.

## Coverage Priorities

Coverage is interpreted by behavior, with particular attention to:

- credential acceptance and rejection;
- password verification;
- tenant access;
- complete membership composition;
- provider selection;
- provider mismatch;
- federated identity linking;
- issuer and audience validation;
- lifetime validation;
- signature validation;
- supported algorithms;
- OIDC/JWKS failure handling;
- cancellation;
- persistence constraints;
- email canonicalization.

## Provider Coverage

Unit coverage demonstrates deterministic authentication and validator behavior.

Integration coverage demonstrates real persistence behavior independently for PostgreSQL, SQL Server and MySQL.

A path covered by one database provider is not automatically evidence that all providers execute it identically.

## Policy

The project follows:

```text
TEST -> RED -> Source -> GREEN -> Coverage -> PR -> merge
```

Coverage is an audit signal, not the objective.

A new test must be justified by a behavior, security requirement or regression. Trivial or artificial tests must not be added solely to increase percentages.

## CI Configuration

Coverage is generated by `.github/workflows/coverage.yml` using Cobertura and a runsettings file that includes the production Auth assembly while excluding the test assemblies and compiler-generated code.

Coverage numbers in documentation must only be updated from a current CI or locally reproduced artifact.
